Bantuan & Panduan

Panduan lengkap memakai dashboard MINT — dari menyalakan stack sampai menarik dataset anomali untuk laporan.

Panduan Cepat (5 langkah)

1
Nyalakan stack server — klik dua kali mulai_stack.bat. Docker Desktop akan menjalankan Mosquitto (broker MQTT), InfluxDB, dan Grafana. Tunggu ±30 detik, lalu cek cek_lingkungan.bat sampai semua centang hijau.
2
Buka dashboard — klik jalankan_dashboard.bat lalu akses http://localhost:5000. Masuk dengan akun Anda (bawaan: admin / mintadmin).
3
Nyalakan perangkat ESP32 — begitu node menyala dan publish ke broker, kartu node di Beranda menyala hijau dan nilai sensor (suhu, jarak, cahaya, foto) tampil realtime. Belum punya perangkat? Uji dengan python scripts/test_publish.py --foto.
4
Jalankan analyzer — klik jalankan_analyzer.bat (atau jalankan_demo.bat untuk mode demo tanpa perangkat). Analyzer menghitung PPS/BPS per detik dan membandingkannya dengan threshold hasil kalibrasi.
5
Pantau & tarik dataset — serangan (flooding, payload besar) memunculkan banner merah SERANGAN TERDETEKSI. Buka halaman Anomali & Dataset lalu klik tombol Unduh untuk menyimpan CSV/JSON bukti pengujian.

Membaca Halaman Node

Status kehadiran (TERHUBUNG / OFFLINE) dihitung dari bukti terbaru, bukan data lama. Sumber bukti (tertera di kartu):

  • ping — node menjawab ICMP ping (dicek tiap 5 detik). Node mati akan tertandai OFFLINE dalam ≤ 15 detik.
  • mqtt — pesan sensor terakhir diterima broker dalam batas wajar (2,5 × interval publish node).
  • trafik — analyzer masih melihat paket dari IP node ini.
  • lwt — firmware mengirim Last Will “offline” (bila didukung).

Kalau tidak ada perangkat yang menyala, angka node terhubung = 0 — dashboard tidak pernah “mengarang” node online dari data basi.

Nilai sensor realtime diambil langsung dari subscribe iot/# di broker: suhu (°C), kelembaban (%), jarak (cm), cahaya (lux). Format payload JSON maupun teks biasa sama-sama dikenali. Pembacaan berumur lebih dari interval publish akan tampak pudar bertanda umurnya.

Foto live dari ESP32-CAM: setiap payload JPEG pada topik iot/kamera langsung tampil di kartu (badge merah LIVE). Klik “buka penuh” untuk melihat resolusi penuh.

Metrik & Cara Kerja Threshold

Setiap detik, analyzer menghitung tiga metrik per perangkat dari paket MQTT PUBLISH yang tertangkap tshark:

  • PPS — jumlah PUBLISH per detik. Naik drastis = indikasi flooding (skenario S1/S2/S4).
  • BPS — total byte per detik. Membengkak = volume trafik abnormal.
  • avg_pkt_size — rata-rata byte per pesan. Membesar = payload abnormal / oversized (skenario S3).

Threshold tiap metrik dikalibrasi dari trafik normal: threshold = median + 3 × 1,4826 × MAD (hasil threshold_baseline.py), sehingga ambangnya menyesuaikan karakter tiap node — kamera boleh besar, sensor suhu kecil.

Aturan pemicu ALERT (agar tidak gampang false alarm):

  • 2-of-3 — minimal 2 dari 3 window terakhir di atas threshold.
  • Override — langsung ALERT bila PPS/BPS ≥ 5× threshold atau avg_pkt_size ≥ 3× threshold.
  • Recovery — ALERT kembali normal setelah 60 detik tenang.
  • Cooldown — notifikasi Telegram duplikat ditekan 30 detik.

Tanda indikasi S1/S3/S4 pada log adalah perkiraan skenario, bukan diagnosis final — verifikasi lewat grafik dan pcap.

Menarik Dataset Anomali

Halaman Anomali & Dataset menyimpan dua jenis bukti:

  • Window > threshold — setiap detik yang melampaui ambang (pps, bps, atau avg_pkt_size), lengkap dengan nilai dan rasionya. Ini dataset mentah penelitian, otomatis tercatat selama analyzer berjalan ke run/anomaly_windows.csv.
  • Event deteksi — ringkasan episode ALERT/RECOVERY dari mesin deteksi (sudah menerapkan 2-of-3, override, recovery).

Klik tombol Unduh … (CSV/JSON) di bagian atas halaman untuk menyimpannya. Berkas hasil perekaman sesi (run_session.py / pcap_analyzer.py) di folder data/ juga bisa diunduh dari tabel paling bawah.

Alur pengujian yang disarankan:

  1. Pastikan threshold terkalibrasi (indikator di footer: “threshold: terkalibrasi”).
  2. Jalankan analyzer (live) atau run_session.py --label S1.
  3. Jalankan skenario serangan dari mesin penyerang — sekarang cukup python scripts\attack_sim.py S1 (laptop penyerang; opsi --rate, --duration, --target, --size; daftar lengkap: --list).
  4. Buka Anomali & Dataset → verifikasi window & event masuk.
  5. Unduh CSV → olah di Excel/pandas untuk Bab 6 laporan.

Fitur Dasar Dashboard

Tema gelap / terang — tombol bulan/matahari di kanan atas. Pilihan tersimpan di browser dan otomatis mengikuti tema sistem saat pertama kali dibuka.

Ganti kata sandi & tes Telegram — klik nama akun Anda (Pengaturan) di kanan atas. Sesi login berakhir otomatis setelah 30 menit idle; 5× gagal login = IP dikunci 5 menit.

Grafik PPS — menu /pps: 4 panel realtime (PPS, B/s, distribusi, ukuran paket) refresh 1 detik tanpa Docker. Grafana asli tetap tersedia di localhost:3000 untuk analisis time-series InfluxDB (login admin/admin) bila stack Docker dijalankan.

Data demo tanpa perangkat — jalankan_demo.bat memutar ulang data/demo_serangan.csv 10× lebih cepat: banner merah, 9 ALERT, dataset anomali terisi — cocok untuk latihan presentasi.

Menu Serangan — Uji Skenario dari Web (baru v8.1; deteksi realtime v9.2.5)

Halaman Serangan menggantikan kebiasaan mengetik perintah di Serial Monitor atau CMD. Pilih kartu skenario (S1–S4), pilih node target dari dropdown (semua node terdaftar tampil — v8.2), atur rate/durasi, lalu tekan MULAI SERANGAN. Sistem menjalankan scripts/attack_sim.py dari laptop server sebagai penyerang; tombol STOP menghentikannya kapan saja, dan keluaran attack_sim tampil langsung di halaman. Sejak v8.2 dampak serangan pasti terlihat di Beranda (banner + grafik PPS) dan menu Anomali (window ditandai kode S1–S4) karena metrik tshark + MQTT digabung.

  • S1 — High-frequency publish: banjir pesan konstan (default 100/dtk, 60 dtk) → PPS melonjak → ALERT PUBLISH-FLOOD.
  • S2 — Message burst: gelombang 50 pesan berulang dengan jeda acak → pola gigi gergaji di grafik PPS.
  • S3 — Payload abnormal: pesan besar >200 KB/dtk → BPS & ukuran paket melonjak → ALERT OVERSIZED-PAYLOAD.
  • S4 — Multi-device burst: 4 topik node diserang serentak → semua node ALERT bersamaan (indikasi serangan terdistribusi).

Tombol Tes Sistem di halaman yang sama memeriksa sekaligus: broker, subscribe sensor, tshark, sumber metrik, InfluxDB, Grafana, dan Telegram — praktis sebelum demo. Catatan: serangan web ber-asal dari IP laptop server; untuk demo dua laptop (IP penyerang terpisah) jalankan attack_sim.py lewat CMD di laptop penyerang.

Menu Grafik PPS — 4 Panel Realtime (baru v8.3)

Halaman Grafik PPS (menggantikan menu Grafana ter-embed) menampilkan grafik realtime buatan sendiri yang refresh tiap 1 detik tanpa perlu Docker: (1) Packet Rate per Perangkat (PPS) lengkap dengan garis threshold putus-putus dan nilai terkini di ujung tiap garis, (2) Byte Rate per Perangkat (B/s), (3) doughnut Distribusi Trafik per Node, (4) Rata-rata Ukuran Paket per Node — plus tabel node realtime (IP, topik, PPS, B/s, total pesan). Paling sering dipakai saat uji serangan: lonjakan S1/S2 langsung terlihat di panel PPS, S3 di panel B/s & ukuran paket. Grafana (mulai_stack.bat) tetap bisa dipakai terpisah di localhost:3000 bila ingin analisis jangka panjang.

Kenapa PPS/BPS Sekarang Selalu Terbaca? (v8.1)

Sejak v8.1, dashboard sudah memuat analyzer di dalam prosesnya — cukup jalankan jalankan_dashboard.bat, tidak perlu lagi membuka jendela analyzer terpisah. Sumber metriknya otomatis (tertulis di panel Kesehatan Sistem dan sub-kartu KPI):

  • tshark (interface …) — terintegrasi: dipakai bila Wireshark terpasang; perangkat dikenali dari IP (paling akurat, cocok dengan pcap/Grafana). Interface dipilih otomatis; pakai variabel MINT_IFACE bila salah tebak.
  • MQTT langsung (fallback): dipakai bila tshark tidak ada/gagal — PPS/BPS dihitung dari pesan yang diterima subscribe iot/#; perangkat dikenali dari topik. Inilah alasan metrik tidak pernah 0 lagi selama broker menyala.

jalankan_analyzer.bat tetap tersedia untuk sesi mandiri (rekam pcap/kalibrasi/replay) — saat dia aktif, analyzer terintegrasi otomatis menyingkir (standby) lalu kembali mengambil alih begitu ditutup.

FAQ / Pemecahan Masalah

Nilai sensor tidak muncul di kartu node

Pastikan (1) broker Mosquitto jalan (mulai_stack.bat), (2) panel Kesehatan Sistem di Beranda menunjukkan “MQTT cache AKTIF”, (3) firmware publish ke topik yang terdaftar di devices.json (mis. iot/suhu). Payload apa pun (JSON atau teks angka) akan dikenali; kalau tetap kosong, cek dengan python scripts/test_subscribe.py apakah pesan benar sampai ke broker.

Status node selalu OFFLINE padahal perangkat menyala

Dashboard menilai kehadiran dari ping/mqtt/trafik. Cek: IP di devices.json sama dengan IP asli ESP32 (lihat serial monitor), laptop dan ESP32 satu subnet (192.168.7.x), dan firewall Windows tidak memblokir ping. Sumber bukti yang dipakai tertulis kecil di kartu node.

Foto kamera tidak tampil

Foto hanya tampil bila payload benar-benar JPEG (diawali byte FF D8). Firmware ESP32-CAM standar sudah seperti itu. Untuk uji tanpa perangkat gunakan python scripts/test_publish.py --foto.

Banner “MENUNGGU DATA” terus-menerus

Sejak v8.1 analyzer sudah terintegrasi di dashboard. Banner ini hanya muncul bila belum ada pesan sama sekali (broker mati atau node belum menyala) — cek panel Kesehatan Sistem / tombol Tes Sistem di menu Serangan. Untuk demo tanpa perangkat: python scripts/test_publish.py atau jalankan_demo.bat (mode replay).

Metrik PPS/BPS terbaca tapi “MQTT langsung” — apa artinya?

Berarti tshark/Wireshark tidak tersedia sehingga metrik dihitung dari pesan MQTT yang diterima dashboard (perangkat dikenali dari topik). Semua fitur deteksi tetap jalan; bedanya serangan dari laptop lain tercatat pada topik yang diserang, bukan pada IP penyerang. Instal Wireshark bila ingin atribusi per-IP seperti data pcap.

Halaman Anomali kosong

Window hanya tercatat bila (1) analyzer sedang berjalan, (2) thresholds.json sudah dikalibrasi, dan (3) ada trafik yang melebihi threshold. Mode demo otomatis mengisi tabel ini. Data lama tetap ada selama file run/anomaly_windows.csv tidak dihapus.

ModuleNotFoundError: flask / psutil

Install dependensi host: pip install -r requirements.txt di terminal proyek (pastikan venv aktif bila memakai venv).

tshark tidak terdeteksi

Installer Wireshark tidak menambah PATH. Jalankan set PATH=%PATH%;C:\Program Files\Wireshark lalu buka terminal baru, atau biarkan MINT mendeteksi lokasi instalasinya otomatis.

ESP32 tidak bisa connect ke broker

Pastikan IP laptop = 192.168.7.101 (set IP statis), Docker mem-publish port 1883, dan firewall membuka TCP 1883: netsh advfirewall firewall add rule name="MQTT" dir=in action=allow protocol=TCP localport=1883.

Lupa kata sandi dashboard

Gunakan python dashboard/add_user.py dari terminal untuk mengganti sandi akun mana pun.
